# Sokone（底値） - 要件定義書

> 最終更新: 2026-02-26

## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| **アプリ名** | **Sokone**（底値） |
| **リポジトリ名** | `sokone` |
| **コンセプト** | チラシ・Instagram・自撮り写真から商品価格を読み取り、底値データを蓄積・可視化するWebアプリ |
| **公開** | GitHub Public Repository |
| **ライセンス** | MIT（予定） |

### 1.1 背景・課題

- スーパーのチラシ、Instagram、店頭で見た価格情報が散在しており、「この商品の底値はいくらか」を把握しづらい
- 底値を知ることで、セール時に「本当に安いのか」を判断できるようになる

### 1.2 ゴール

- 複数のデータソース（チラシ画像、Instagram投稿、店頭撮影写真）から商品名と価格を自動抽出
- 商品ごと・店舗ごとの価格履歴を蓄積し、底値を特定・表示
- ユーザが自分の生活圏の店舗を登録して、パーソナライズされた底値情報を得られる

## 4. データ収集ソース

### 4.1 ユーザ撮影写真（Phase 1 MVP）

| 項目 | 内容 |
|---|---|
| **概要** | ユーザがスーパー店頭で撮影した値札・POP・棚の写真をアップロード |
| **処理フロー** | 画像アップロード → 店舗選択 → OCR解析 → 商品名＋価格の自動抽出 → ユーザ確認・修正 → 登録 |
| **対応形式** | JPEG, PNG, HEIC（スマホ撮影形式） |
| **一括対応** | 複数画像の同時アップロード対応 |

#### 店舗選択UX（ハイブリッド方式）

アップロード時の店舗紐付けは、手軽さとデータ品質を両立するハイブリッド方式を採用する。

```
写真アップロード画面
├── 📍 位置情報ON → 近くの店舗を自動候補表示（登録済みなら先頭に）
├── 🏪 登録済み店舗リストから選択
├── ➕ 「新しい店舗を追加」→ 店舗名入力 → そのまま登録＆紐付け
└── ⏭️ 「あとで設定」（店舗未指定でもアップ可能）
```

| 方式 | 説明 |
|---|---|
| **登録済み店舗から選択** | ワンタップで選択。リピート利用時に最も楽 |
| **新規店舗をその場で追加** | 初めての店舗でも登録画面に遷移せずそのまま追加可能 |
| **GPS自動候補表示** | 位置情報から近くの店舗を候補表示（Phase 1ではWeb Geolocation API、Phase 5でネイティブGPS） |
| **店舗未指定でアップ可能** | 店頭で素早く撮影→後から店舗を設定。登録忘れ防止のリマインドあり |

### 4.2 WEBチラシ（Phase 2）

| 項目 | 内容 |
|---|---|
| **概要** | チラシ画像をアップロードまたはURL指定で取得し、OCRで解析 |
| **店舗管理** | ユーザが監視対象の店舗を手動登録 |

#### チラシ収集方法の検討

| 方法 | 実現性 | 採用 | 備考 |
|---|---|---|---|
| **ユーザ手動アップロード** | ◎ | ✅ Phase 2 | チラシのスクショやPDFをアップ → OCR解析。最も確実 |
| **チラシ画像URL指定** | ○ | ✅ Phase 2 | ユーザがURLを貼る → 画像取得 → OCR解析 |
| **各スーパー公式サイトスクレイピング** | ○ | 🔜 Phase 4 | 店舗ごとにスクレイパー実装。合法的に取得しやすい |
| **Shufoo! / トクバイ** | △ | ❌ 非推奨 | 公開APIなし。スクレイピングは利用規約違反の可能性大 |
| **Google検索経由** | △ | ❌ 非推奨 | 安定性に欠ける |

> **方針:** Shufoo!/トクバイ等の外部サービスはAPIが公開されておらず、スクレイピングは利用規約違反リスクがあるため採用しない。ユーザ手動アップロード＋URL指定をベースとし、将来的に主要スーパーの公式サイトから合法的に自動取得する仕組みを段階的に追加する。

### 4.3 Instagram連携（Phase 3）

| 項目 | 内容 |
|---|---|
| **概要** | スーパー等の公式Instagramアカウントのセール投稿から価格情報を取得 |
| **方法A（推奨）** | ユーザがInstagram投稿のスクショを手動アップロード → OCR解析 |
| **方法B（将来）** | Instagram Graph API（Metaビジネスアカウント連携）で自動取得 |
| **制約** | Meta APIは利用審査必要。個人アカウントでは他者の投稿取得に制限あり |

> **方針:** MVP〜Phase 3では手動スクショアップロードで対応。API連携は需要と実現性を見て判断。

## 6. 非機能要件

| 項目 | 内容 |
|---|---|
| **レスポンス** | 画像アップロード〜OCR結果表示：10秒以内 |
| **同時利用** | 初期は少人数想定（〜100ユーザ） |
| **データ保持** | 価格履歴は無期限保存 |
| **セキュリティ** | HTTPS、APIキーの環境変数管理、OAuthトークンの安全な管理 |
| **価格表示** | 税込価格に統一（税抜表示の場合はOCR抽出時に×1.08/1.10で換算） |
| **モバイル対応** | レスポンシブデザイン（スマホでの利用が主） |

## 7. 技術スタック

### 7.1 確定スタック

| レイヤー | 技術 | 理由 |
|---|---|---|
| **Frontend** | **Next.js 14+ (React) + TypeScript** | SSR/SSG対応、将来React Native移行しやすい |
| **UI** | **shadcn/ui + Tailwind CSS** | 軽量・カスタマイズ性高。Next.jsと相性抜群 |
| **Backend** | **Python (FastAPI)** | OCR/AI処理との親和性が高い、非同期処理対応 |
| **DB** | **PostgreSQL** | 価格履歴の構造化データ管理、全文検索対応 |
| **ORM** | **SQLAlchemy + Alembic** | Python定番のDB操作＋マイグレーション |
| **認証** | **NextAuth.js (Auth.js) + Google OAuth** | MVPはGoogle OAuthのみ。シンプルかつ安全 |
| **開発環境** | **Docker Compose** | PostgreSQL含め一発で環境構築 |
| **Python** | **3.12** | 安定版、パフォーマンス改善 |
| **Node.js** | **22 LTS** | 最新LTS |

### 7.2 OCR/AI戦略（コスト最適化）

**目標：可能な限り無料で運用**

#### メイン構成：Google Gemini 2.0 Flash（無料枠で運用）

Gemini 2.0 Flash は画像を直接入力でき、OCR（文字認識）と構造化抽出（商品名・価格のJSON化）を
**1回のAPIコールで同時実行**できる。これにより Cloud Vision API を別途呼ぶ必要がなくなり、
アーキテクチャがシンプルになる。

| 処理 | メイン（無料） | 代替プロバイダ（有料・安価） | フォールバック（無料・ローカル） |
|---|---|---|---|
| **OCR＋構造化抽出** | **Gemini 2.0 Flash**（1日1,500リクエスト無料） | GPT-4o-mini（$0.15/1M input tokens） | Tesseract + Ollama |
| **商品名寄せ** | 編集距離＋ルールベース | Gemini Flash / GPT-4o-mini | ルールベースのみ |

#### Gemini 2.0 Flash vs GPT-4o-mini 比較

| 項目 | Gemini 2.0 Flash | GPT-4o-mini |
|---|---|---|
| **コスト** | **無料**（1日1,500 req / 1分15 req） | 有料（Input: $0.15/1M, Output: $0.60/1M） |
| **日本語精度** | ◎ | ◎ |
| **画像直接入力** | ✅ | ✅ |
| **構造化JSON出力** | ✅ | ✅ |
| **速度** | 非常に高速 | 高速 |
| **この用途での精度差** | 実用上ほぼ同等 | 実用上ほぼ同等 |

→ コスト面で Gemini Flash が圧倒的に有利。精度は同等のため、Gemini Flash をメインに採用。

#### 無料枠の整理

| サービス | 無料枠 | Sokoneでの用途 |
|---|---|---|
| **Gemini 2.0 Flash** | 1日1,500リクエスト / 1分15リクエスト | OCR＋構造化抽出（メイン） |
| **Google Cloud Vision API** | 月1,000画像 | 必要に応じてOCR補助（Geminiで十分なら不要） |
| **Tesseract** | 完全無料（ローカル） | フォールバック |

**推奨構成（ほぼ完全無料）：**
1. **メイン** → Gemini 2.0 Flash に画像を直接送信 → OCR＋構造化抽出を一発実行（無料枠内）
2. **代替** → GPT-4o-mini（Gemini障害時、月数百円以内）
3. **フォールバック** → Tesseract + Ollama（全API障害時、完全ローカル）

> **Phase 1 検証事項:** Gemini Flash の画像直接入力でチラシ・値札の商品名/価格抽出精度を検証する。
> 精度が不十分な場合は Cloud Vision API（OCR）→ Gemini Flash（構造化）の2段構成に切り替える。

## 8. データモデル（概要）

```
User（ユーザ）
├── id, email, name, password_hash, created_at

Store（店舗）
├── id, name, address, area, user_id, created_at

ProductCategory（商品カテゴリ）
├── id, name, parent_id（階層構造）

Product（商品マスタ）
├── id, name, normalized_name, category_id, unit, volume
├── aliases: ProductAlias[] （名寄せ用の別名リスト）

PriceRecord（価格記録）
├── id, product_id, store_id, user_id
├── price, unit_price（100gあたり等）
├── source_type（photo/flyer/instagram）
├── source_image_url
├── recorded_at, created_at

BottomPrice（底値サマリ）※ビューまたはマテリアライズドビュー
├── product_id, store_id
├── bottom_price, bottom_price_date
├── average_price, latest_price

UploadedImage（アップロード画像）
├── id, user_id, store_id, image_url
├── source_type, ocr_result_json
├── processed_at, created_at
```
